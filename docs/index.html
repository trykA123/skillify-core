escalation & safety

how the fleet stays honest
one writer per tree

One worker at a time per working directory — never parallel writers on the same tree. Atomic per-slice commits keep every change small and revertible.

decisions escalate

Product, architecture, and safety decisions go up via contact_supervisor (need_decision). The conductor never decides them itself; children never decide silently.

dry-run by default

planner, reviewer, and oracle are read-only — they plan, judge, and check without touching a file. Only the worker writes.

repair loop, capped

worker → reviewer runs up to 3 rounds. If still unresolved, the conductor escalates to the parent instead of settling silently.

acceptance by evidence

The reviewer verifies from code, tests, docs, or requirements — never guessing. “Did the worker actually edit files? Did the findings get addressed?”

no secrets in the fleet

Model names and skill names are versioned; no keys, tokens, passwords, or auth URLs ever live in agent files or fleet config.

the parent gate · review in my place

Before anything ships, the parent reviews every diff the way the owner would — then changes what the owner would complain about, preemptively. The owner's taste, applied by the strongest model at review time.

the owner's taste checklist
  • 1.250 type scale @ 20px — zero px, zero off-scale sizes, anywhere
  • WCAG AA contrast in both themes (washi + sumi)
  • vertical centering; text always fits its container
  • mobile-first: ≤ 6 rows per page, then paginate — no infinite scroll
  • topbar-first navigation; no bottom tabs
  • no search — the palette stays dead
  • stats live where they belong (telemetry with its domain)
  • zen/sumi-e language: oklch tokens only, no hardcoded colors
  • honest numbers — 2 decimals, real names, nothing misleading
  • order over sprawl: tabs, collapsibles, fewer places to check
