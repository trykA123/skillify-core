§8The fix listconcrete · verifiable · an afternoon's work

Everything below is a defect in the skills as written — not a taste call, not a maybe. Each was verified against the current files in this pass.

promptify/SKILL.md · frontmatter
Stale description advertises gamification the body forbids
Description: "saved as a lesson + glossary, with gamified progress." Body: "No XP. No streaks. No badges." Harnesses surface the description to decide invocation — it currently misrepresents the skill. Rewrite around "evidence-based skill map."
explainify/SKILL.md · Final Gate
Unconditional artifact checkbox contradicts the chat-first default
Gate: "Knowledge doc saved or updated in place." Step 4: "If none of the escalation criteria fire: skip this step entirely." A compliant executor following the gate re-introduces the exact ceremony v2 removed. Make the gate conditional: artifact-if-escalated, else chat-only declared.
README.md · "The Ceremony Dial" vs explorify/SKILL.md
"Each skill has a lite/quick path" — false for explorify
Every other skill has an explicit lite/quick mode with escalation criteria. Explorify has none; every activation pays full sketch ceremony. Add Quick Explore (2 options × 3 lines, escalate if the user can't choose) or correct the README claim.
game-layer.md vs undumbify + traceify
Passive harvesting is half-wired
game-layer.md claims pipeline-wide harvesting ("undumbify had to ask 3 questions → under-specified prompt", "traceify resolved in 2 hypotheses → good symptom description"). Only shipify and reviewify actually emit a "Skill map signal" line. Add the one-line signal to undumbify's Intent Brief and traceify's Diagnosis Report — or strike those two examples from the spec. (This is exactly the structural hook RATINGS.html asked for; it got built in two of four skills.)
promptify/SKILL.md · Final Gate vs game-layer.md
Gate demands dashboard regeneration; spec says render is optional
Gate: "Skill map updated: evidence appended, dashboard regenerated." game-layer.md: "If the render is skipped (no Node, agent forgot, context is tight), nothing breaks… skip silently." Soften the gate to "render when Node available." Same issue, milder: the glossary gate line ignores quick mode's chat-only path.
shipify/SKILL.md · step 1 vs README "just do it" override
No packet-less execution path
The README override says "Skip shapeify's packet — execute directly, verify at the end," but shipify's step 1 validates a packet and has no fallback shape for direct execution. Add a micro-packet (outcome / steps / done-when, three lines) so the override has a defined landing spot.
orientify + explainify · rtk references
Harness-specific tooling in a harness-agnostic system
"Prefer rtk-wrapped commands (rtk git log, rtk tree…)" — rtk is this user's local proxy, not a harness feature. Already gated with "when available," so it degrades gracefully; still, it's the only place the README's "any agent that reads markdown" claim leaks. Remove or footnote.
undumbify/SKILL.md · six dimensions
Junior vocabulary wall (all four raters, cheapest available fix)
The plain-language phrasing instruction exists but is buried below the dimensions. Hoist a one-line alias table to the top ("feeling of done = how will you know it's right? · pushback permission = can I tell you no?"). Formal names stay for the Intent Brief. Every rater's junior score (7.0–8.1) says this is the highest-leverage adoption fix in the repo.
system · measurement, not code
The ratings themselves are noisy — treat all numbers as ±0.3
