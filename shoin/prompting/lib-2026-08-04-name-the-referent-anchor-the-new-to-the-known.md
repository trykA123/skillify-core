# Name the referent; anchor the new to the known

**Principle:** Name the referent; anchor the new to the known.

**Why:** A nickname given without a key — a big-brother node, the lighting — forces an interpretive round-trip and risks silent misassignment; naming the concrete referent in the same message makes the metaphor free. A new feature is specified by the data it consumes plus the pattern it copies — a new chart inherits the card values and the filter of an existing chart — so two citations replace a design conversation.

**When to apply:** metaphors and new-feature specs where the referent and the template must land in one message.

**When not to:** when the audience provably shares the exact referent and the anchor is redundant.
