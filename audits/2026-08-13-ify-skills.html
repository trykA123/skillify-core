The Standard

Derived from the skills' own stated goals and the README's commitments. Five criteria, each testable:

  1. Internal consistency — each skill's claims about itself (what it does, where it routes, what it references) match what actually exists in the repo
  2. Chain integrity — the pipeline chain (orientify → undumbify → shapeify → shipify → reviewify) is wired: each skill names its downstream handoff
  3. Structural coherence — the 12 skills share enough structural convention to be recognizable as one family; frontmatter and metadata are consistent
  4. Executable references — paths, commands, and file references in the skills resolve to real things
  5. Self-description accuracy — the README's claims about the skill set match reality (counts, names, labels, taxonomy)

F9 Terminal section naming varies: "Before you emit/ship/close/finish" across 7 skills Accept
Criterion 3 (structural coherence) · All SKILL.md files

7 of 12 skills have a "Before you…" terminal section, using 4 different verbs: emit (researchify, reviewify, shapeify, undumbify), ship it (audify), close (traceify), finish (shipify). 5 skills (librify, explainify, recordify, promptify, orientify) use "Done when" or "Then" instead, or have no explicit terminal guard.

The variation is intentional — each verb matches the skill's cognitive mode (you "emit" findings, "ship" an artifact, "close" a bug, "finish" a build). But a reader encountering the family would need to learn where the self-check lives in each skill.

Evidence

Intentional variation — accept as-is. The verb differences are meaningful and the section is consistently the last heading in every skill that has one.
