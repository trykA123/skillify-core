# Delegate the how, keep the what — bounded freedom grants x4; challenge-with-evidence applied; artifact delta checks

## What happened
A long build session that delegated the how while keeping tight hold of the what — bounded freedom grants, verification asks before acceptance, and challenge-with-evidence applied to the numbers. The ceremony matched the risk at every step.

## What worked
- Constraints before the ask, every round: no three.js, flat HTML only
- Chose the modern color format for easier palettes — the tool constraint stated up front
- Marked the reference read-only while granting freedom on structure — limits and latitude both explicit
- symbols are only relevant for table — killed a leak before it spread
- Volunteered the mobile-first priority in the same message as the brief
- Specified the type scale and contrast rules before any guessing — three hard limits up front
- Narrowed the model set to two and banned the fallback — hard limit before any work started
- Drew the privacy boundary up front — no sensitive data, generic stand-ins where needed
- Simplified the ratio precision and granted color freedom — constraint and latitude in one spec
- Feedback scored and ordered, critical first — the top issue named with its score
- Kept the winning concept but rebuilt from zero — the clash resolved by naming what wins
- Final rounds: one concern per file, never mixed topics
- Kept the theme direction but changed the layout — what wins stated when two directions clashed
- Stated the single priority — everything else explicitly excluded
- Flagged pagination as the priority inside a numbered spec — the executor orders work around it
- numbered additions 1-4 (2dp ratio, AV1 name, availability column, colors) — ordered, each atomic
- Caught the dangling arrow and asked where it points — a real proof-ask
- Asked for ground truth on the model options before accepting the capability table
- Verified the styles used the intended color format — checking the implementation against intent
- Asked for the type ratios to be checked — verification before accepting the design
- Challenged the cost model with the observed bill — the correction was worth an order of magnitude
- Asked that the designs match the established theme — verification before acceptance
- Asked whether the background job had deleted or changed anything — verification about system state, not claims
- Have the new skill be tested to see if it truly works — test-don't-assume extended to the fleet's deliverables
- Challenged a misleading number in the produced artifact and demanded the reconciliation be written down
- Knew three.js would be needed for the spatial concepts under the flat-HTML constraint
- Offered the artifact choice — a tab or a summary — and let the concept decide
- Asked to render the artifact for review — the right artifact, every time
- Insisted the plan be a durable, committable artifact
- Asked whether the artifact would regenerate — artifact-aware
- Followed the proven reference artifact for the redesign — the right artifact picked
- Shaped the deletion record format in detail — header, stacked columns, collapsibles, colors — knowing exactly what the artifact should contain
- Ran the *ify loop on the agent: intent extraction on vague rounds, bug reports on broken ones, scored verdicts every round
- Reached for the right skill at the right moment across 8 rounds of review
- Corrected the lens by name and invoked the right teaching skills for the debrief
- Re-invoked the teaching loop with the latest prompts — at the natural moment, no prompting needed
- Policed a pipeline violation — the doc should have been planned, not improvised
- Re-invoked the teaching loop at the natural checkpoint before signing off
- Delegated a taste-review to the system — the meta-move of testing whether it had learned the preferences
- Re-invoked the teaching loop on the latest discussion — at the checkpoint, again
- Knew when lite (just make the height bigger) vs full (redesign from zero) earned its keep
- one screen, one fix preference held all session
- Deferred the ceremony and handled the thinking per decision — sized each one deliberately
- Full orchestration for the rebuild, dry-run default for the seeding pass — ceremony matched risk
- Scoped the ask honestly before requesting — the strongest setting requested knowingly for design work
- Matched the most capable models to the review and sized the delegation — ceremony matched stakes

## What didn't
- Seed rules shipped without a minimum-ratio or exists-guard — the safety constraints had to be surfaced from outside
- Re-reviewed a stale tab twice (still can only see two skills) — the version wasn't named
- full rebuild session banked no durable wiring doc — the recon lived in an ephemeral scout handoff
