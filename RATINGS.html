Per-Skill Cards (v2)

🧭 orientify standalone

8.5
▲ +0.1 from v1
What improved: Quick Orient (5-line brief) means small repos and narrow questions no longer trigger the full scan + deletion test + hot-spot analysis. The escalation path ("if quick brief reveals hidden complexity → go full") is clean.

Remaining gap: Still somewhat redundant for seniors who already know how to read a codebase. But that's fine — its primary audience is subagents and cold-starts.

🔭 explorify standalone

8.9
— unchanged
Why untouched: Was already the best-designed skill. "Axes not variations" + mandatory sketches + the remix/expand/reject interaction model. Nothing to fix. The low trigger frequency is inherent to its purpose (divergence is rare), not a design flaw.

🎯 undumbify pipeline

8.8
— unchanged
Why untouched: The Materiality Gate + context-awareness (known/assumed/unknown) is the correct design. Six dimensions are well-chosen. The "feeling of done" dimension still feels slightly forced for technical users, but the escape hatch ("or confirmed as acceptance criteria suffice") handles it.

📐 shapeify pipeline

8.6
▲ +0.6 from v1 — biggest mover
What improved: Step 0 (Choose Packet Weight) is the fix. Lite packet = 5 fields, done. Full packet only when complexity demands it. "When in doubt: lite" is the right default gravity. The escalation path (lite fails → shipify requests re-shape as Full) preserves safety without front-loading cost.

Remaining gap: The full packet template is still 15+ fields. But now it's only reached when justified, so the weight is earned rather than imposed.

🚀 shipify pipeline

8.5
▲ +0.1 from v1
What improved: Single-agent completion report is now 3 lines (done/deviations/follow-ups). The full table is reserved for subagent/plan-folder mode where the reader wasn't in the room. Small change, right instinct.

Remaining gap: Still depends on shapeify producing a good packet. But the lite/full split means simple tasks get simple packets, reducing the garbage-in surface.

🔍 reviewify pipeline

8.9
▲ +0.3 from v1
What improved: "Select 3–4 lenses, go deep" with a selection heuristic (Req fit + Invariant safety always in, pick 1–2 more from what the diff touches). This kills checklist fatigue and produces higher-signal findings. "State which lenses you skipped" keeps it honest without forcing coverage theater.

Remaining gap: Minimal. The solo/full mode split + deep lenses + capped advisories = a review skill that respects everyone's time.

🩺 traceify standalone

8.9
— unchanged
Why untouched: Tightest skill in the set. Falsifiable hypotheses, cheapest-test-first, trivial/non-trivial fork, "do NOT stack workarounds." Every rule is load-bearing. The only skill where I'd say "don't change a word."

🗣️ promptify teaching

8.5
▲ +0.6 from v1 — tied biggest mover
What improved: Two changes, both structural. (1) Quick mode is the default — full ceremony requires explicit escalation criteria. A conciseness teacher that's concise. (2) Skill map replaces XP/streaks/badges — evidence-based competency tracking instead of generic gamification. "P1 → developing: you led with intent today" is actionable; "+10 XP — Level 2: Tinkerer" is not.

Remaining gap: Still requires Node.js for the renderer. Still writes to ~/.agents/learnings/. These are acceptable costs for the tracking value, but they remain the heaviest dependency in an otherwise zero-dep system.

🧠 explainify teaching

8.4
▲ +0.5 from v1
What improved: Chat-first default. "What does this function do?" → answer in chat, update profile, done. Artifacts (knowledge doc, HTML, SVG diagram) only when: 3+ modules, user explicitly asks, or repeat question. The escalation criteria are specific and falsifiable — no judgment calls.

Remaining gap: The SVG diagram generation is still error-prone for AI executors (getting inline SVG right in one shot is hard). But now it's only attempted when genuinely earned, so the failure cost is lower.

System-Level: What's Better Now

✅ Improvements that landed

  • Ceremony dial is real. Every skill now has an explicit lite/quick path with clear escalation criteria. The README's "Ceremony Dial" section makes the philosophy visible.
  • Adoption path exists. "Start Here" in the README: traceify + undumbify first, add pipeline when you feel the pain, teaching cluster last. No more 9-skill wall.
  • Teaching cluster practices what it preaches. promptify teaches conciseness → is concise. explainify teaches "right artifact for the question" → defaults to chat.
  • Skill map > gamification. Evidence-based competency tracking with passive harvesting from the whole pipeline. The dashboard shows what to work on next, not how many streaks you have.
  • Token cost reduced. Lite packets, lean reports, chat-first teaching, 3-4 lenses instead of 9. The system is ~20% lighter in typical execution.
  • AI executor happiness up. Clearer defaults = fewer wrong-path executions. "When in doubt: lite" / "Default: chat-only" / "Select 3-4 lenses" are unambiguous instructions.

⚠️ Remaining gaps (honest)

  • Node.js dependency persists. The skill map renderer still needs Node. For a system that's otherwise "just markdown," this is the one odd weight. Acceptable, but worth noting.
  • Passive harvesting is aspirational. The game-layer spec says pipeline skills should note evidence passively. But shapeify/shipify/reviewify don't have explicit "note evidence for skill map" steps. It relies on the agent remembering to do it. Could be more structural.
  • undumbify's junior score is still 7. The six dimensions + Materiality Gate are correct design, but a junior seeing "feeling of done" and "pushback permission" as required fields might bounce. The invocation brake helps, but the skill's vocabulary is senior-oriented.
  • No "just do it" override in the skills themselves. The README's Ceremony Dial section describes the philosophy, but individual skills don't have a top-level "if the task is trivially small, skip this skill entirely" gate. The invocation brakes are close but per-skill, not system-level.
  • 14 competencies might be too many to track. In practice, most users will have evidence for 4-5 of them. The rest stay "emerging" forever. Consider whether W1-W3 (pipeline) earn their place or should be folded into P/U.

Final Verdict (v2)

8.7 / 10 — up from 8.5. The improvements are surgical and correct.

The v1 criticism was "sophistication vs. adoption friction." The v2 answer is the ceremony dial: every skill now has a lean default path with explicit escalation criteria. The system no longer assumes every task deserves full pipeline treatment. "When in doubt: lite" / "Default: chat-only" / "Select 3-4 lenses" — these three phrases fix 80% of the friction.

The skill map redesign is the boldest change and the most correct. Replacing XP/streaks/badges with evidence-based competency tracking transforms the teaching cluster from "gamified frequency tracker" to "honest mirror of your growth." The passive harvesting concept (pipeline interactions generate evidence without stopping to teach) is elegant — it just needs a slightly more structural hook to be reliable.

What's now best-in-class: traceify (debugging), explorify (divergence), undumbify (convergence), reviewify (judgment). These four are as good as agent prompts get.

What still has room: The pipeline skills (shapeify, shipify) are excellent but their value is proportional to task complexity — they shine at 6+ steps and feel like overhead at 2. The lite packet fixes most of this. The teaching cluster is now philosophically correct but needs real-world use to validate the competency list (are 14 the right 14?).

The one thing I'd still add: A structural hook for passive harvesting — one line in shipify's completion report: "Skill map signal: ." That closes the loop between "the pipeline generates data" and "the skill map records it" without adding ceremony.
